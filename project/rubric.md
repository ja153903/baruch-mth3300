# Project rubric (100 points)

| Category | Points | Full credit | Partial credit |
|---|---|---|---|
| **Oral defense** | 40 | Explains any line we point to, and why it's there. Can say how they'd change it. | Explains *what* the code does, but not *why*; can't explain some sections |
| **Correctness** | 20 | The core works on the spec's example cases and on new inputs we try | The core works on the spec's cases only |
| **Tests** | 15 | 10+ tests covering normal cases, edge cases, and errors; all pass | Fewer tests, or only "happy path" tests |
| **Spec and process** | 10 | `SPEC.md` was written first, and the code matches it (or the changes are explained) | Spec written afterwards, or vague |
| **AI log** | 10 | Shows judgment: suggestions rejected or changed, with reasons | Just a list of prompts |
| **Code quality** | 5 | Clean `ruff` and `ty` runs; clear names; small functions | Some warnings or unclear names |

**Students who can't explain their code can't pass the project.** If someone can't explain the core of their own submission, their total score is capped at 50.
